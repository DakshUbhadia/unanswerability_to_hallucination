### DEV-003 details: token parity, log-popularity matching, and PopQA answer grading

- **Llama tokenizer parity:** Using the tokenizer for `meta-llama/Llama-3.2-3B-Instruct`, `0/384` pairs had `|delta_L| > 2`; maximum `|delta_L|` was `2`. The absolute-delta distribution was `{0: 99, 1: 184, 2: 101}`. All `48` B-control prompts were tokenized; their lengths had a minimum of `43`, median of `50`, and maximum of `63`. The per-prompt and per-pair results are in `results/stage2_llama_parity.json`.

- **Stage affected:** Stage 2, with `meta-llama/Llama-3.2-3B-Instruct` locked for downstream stages in `results/stage2_pilot.json`.
- **Pre-registered branch execution:** Qwen Attempt 1 and Attempt 2 both had a validation unanswerable abstention rate of `1.0000`, above the registered `0.95` ceiling, with answerable abstention at `0.0000`. Branch Rule 1 therefore triggered Attempt 3 using the registered Llama fallback. The fallback passed Stage 0 checks (`28` layers, `d_model = 3072`, `k_suffix = 5`) and Stage 2's validation pilot (`0.9479` unanswerable, `0.0104` answerable, `0.9375` gap; log-odds means differ by approximately `15.01` nats).
- **Frozen dataset tokenizer note:** `data/pairs.jsonl` was built and initially checked under the primary Qwen tokenizer, then measured with the locked Llama tokenizer. The Llama measurement found no pair exceeding the `|delta_L| > 2` threshold; see the parity results above. The dataset prompts and pairs remain unchanged.
- **Popularity-scale deviation:** `s_pop` is retained unchanged in each PopQA row and continues to determine decile ranks. Matching instead uses `log10(max(s_pop, 0) + 1)` for both the population standard deviation and pairwise caliper distances. `caliper_width_s_pop` consequently records a width in log10 popularity units. This is a documented departure from the original raw-scale caliper in the frozen protocol.
- The grader strips trailing generic descriptors from aliases (`film`, `movie`, `music`, `series`, `genre`, `church`, `game`) when they identify a shorter answer. Other partial matches to compound aliases are assigned `ambiguous` and excluded from both correct and wrong groups. For example, `Horror` matches `horror film`; `Hockey` against `ice hockey` is ambiguous.
- Saved-response regrade counts, before → after: correct `185 → 196`; wrong `298 → 253`; abstain `517 → 517`; ambiguous `0 → 34`. The log-popularity rematch now yields `147` matched pairs at caliper `0.236498`, so the `>= 100` power gate still passes. No model responses were regenerated.

### DEV-005 details: Stage 3 float16 batch-vs-single parity

- On Kaggle T4 with `meta-llama/Llama-3.2-3B-Instruct`, an observed batch-vs-single comparison had minimum cosine `0.999990`, maximum per-vector relative L2 `0.004428`, and maximum absolute difference `0.03125`. The original `allclose(rtol=5e-3, atol=5e-3)` check also failed. Since the failing coordinate was not recorded by that run, the maximum difference alone does not establish that it was a one-ULP change at magnitude 40.
- The previous cache passed only the cosine, relative-L2, and absolute-error gate; the diagnostic found 180 elementwise `allclose(rtol=5e-3, atol=5e-3)` failures in `430080` coordinates (maximum violation ratio `2.46`) and float16 ULP distances up to `2512` among the reported worst coordinates. This was not evidence of ordinary one-ULP rounding. The old cache is superseded and must not be used for Stage 4.
- Transformers 4.46.3's Llama model defaults missing `position_ids` to `cache_position.unsqueeze(0)`. With left padding, that assigns column-based positions to real tokens. Stage 3 now derives position IDs from the attention mask so each real token keeps the same RoPE position it has in the unpadded prompt. The parity acceptance gate again requires elementwise allclose in addition to cosine, relative-L2, and dtype-specific absolute checks. Recompute Stage 3 and review the new diagnostic before Stage 4.

### DEV-006 details: left-padding position IDs corrected

- The previous Stage 3 batches supplied `input_ids` and `attention_mask` but no `position_ids`. In the pinned Transformers 4.46.3 Llama implementation, omitted IDs default to sequence-column positions; left-padded answer prompts therefore did not share unpadded RoPE positions. The parity diagnostic for `pair_0001` found 180/430,080 elementwise mismatches, with the worst reported coordinate differing by 32 float16 representable steps and near-zero coordinates differing by much larger ULP counts.
- Batched and single-prompt inputs now explicitly set `position_ids = attention_mask.long().cumsum(-1) - 1`, replacing pad positions with zero. The Stage 3 parity gate requires zero failures under `allclose(rtol=5e-3, atol=5e-3)` as well as the existing cosine, relative-L2, and maximum-absolute bounds. The previous 664 MB cache is not valid for downstream use; regenerate it before Stage 4.

### DEV-004 details: pre-registered Stage 2 fallback executed

- Qwen Attempt 1 and Attempt 2 both observed an unanswerable abstention rate of `1.0000` (above the `0.95` ceiling) and an answerable rate of `0.0000`. The ceiling did not have its own targeted remedy; the implementation followed the generic narrow-gap calibration rule on Attempt 2, so the prompt changed but the measured rates repeated. It then followed the pre-registered Attempt 3 fallback rule.
- `meta-llama/Llama-3.2-3B-Instruct` passed Stage 0 checks (`28` layers, `d_model = 3072`, `k_suffix = 5`) and the Stage 2 validation pilot (`0.9479` unanswerable, `0.0104` answerable, `0.9375` gap; mean log-odds separation approximately `15.01` nats). It is the active model locked in `results/stage2_pilot.json`.
- `data/pairs.jsonl` was built using the primary Qwen tokenizer and then checked using the locked Llama tokenizer; the measured Llama parity results are recorded under DEV-003.
